## [Unreleased]

### Added

- **Inline scan patterns:** `ob scan -e '<regex>'` (`--regex`, repeatable) scans without a YAML patterns file. When any `-e` is given, the patterns file is skipped entirely and patterns are auto-named `inline_1`, `inline_2`, ...
- **`--hidden` / `--no-ignore` scan flags** (ripgrep-style): by default `scan` skips hidden files/directories and anything matched by `.gitignore`/`.ignore` files — which silently hides the most likely secret locations (`.env`, `.github/workflows/`, gitignored config). `--hidden` includes hidden files and `--no-ignore` stops honoring ignore files; the scan help now documents the default exclusions.
- **Dry-run change preview:** `replace --dry-run` now shows what would change, not just how much: each `DRY Modified <file> (N changes)` line is followed by the affected lines as `- old` / `+ new` pairs (deletions as `-`, insertions as `+`), capped at 40 preview lines per file with a `... and N more` note. A change the line diff cannot attribute (e.g. only the trailing newline differs) is noted instead. Per-file blocks are printed atomically, so parallel workers cannot interleave previews.
- **`replace --list-presets`:** prints each built-in preset's kebab-case name with its one-line description (sourced from the same metadata as `--help`, so the two cannot drift) and exits. `--dir` is not required for the listing; a real replace run without `--dir` still errors, and the error now points at `--list-presets`.
- **Positional inputs for `replace`:** `ob replace <INPUTS>...` now takes files and/or directories positionally, mirroring `scan`'s grammar (`ob replace src/ lib/ -p 'TODO' -r '[TODO]'`, `ob replace main.py --preset remove-todos`). Directories walk exactly as before (gitignore-aware, `--exclude`, `.bak` and binary skip); explicit files pass the same filters `scan` applies to explicit files (the `-x` extension filter applies, `.bak` backups are never input, binaries are skipped). A file reached twice — named explicitly and found inside an input directory, or via overlapping directories — is processed once (inputs are deduplicated by canonical path). A nonexistent input path errors like `scan` (`Input path not found: ...`).
- **`scan --no-cache-content`:** keeps matched text out of the on-disk incremental cache. With `--incremental`, the per-project cache normally stores every matched line in plaintext (secrets included, when scanning for secrets); with the flag only pattern names, file fingerprints, and line numbers are persisted, and cache hits re-read just the recorded line numbers from the (fingerprint-unchanged) files to reconstruct the output — one pass per file, not one read per match. If a re-read fails or a recorded line no longer exists, the scan warns to stderr and re-scans that file fresh. The flag requires `--incremental` (an error otherwise); either cache flavor is readable regardless of the flag on later runs — the next save simply follows the current flag.
- **`exclusions` in scan pattern files:** the README documented an `exclusions:` key that no code read, so the listed directories were scanned anyway. A patterns file can now list names to skip (`exclusions: [node_modules, vendor]`). They are matched against the path below each input directory, never against the input's own path, and an excluded directory is not walked, even with `--hidden` or `--no-ignore`. A file named as an input is never excluded. The key has no effect with `-e` inline patterns, which load no patterns file.
- **Shell completions & man page:** `ob completions <shell>` prints a completion script (`bash`, `zsh`, `fish`, `powershell`, `elvish`) and `ob manpage` prints the top-level roff man page. Both write to stdout only — redirect to install (e.g. `ob completions zsh > ~/.zfunc/_oober`, `ob manpage > /usr/local/share/man/man1/oober.1`). Generated by `clap_complete`/`clap_mangen` from the same clap definitions as `--help`, so they cannot drift from the CLI.

### Changed

- **Breaking:** the environment variable for `scan --workers` is renamed from `UBER_SCANNER_WORKERS` to `OOBER_WORKERS`; the old name is no longer read. Remaining "Uber Scanner" branding in the docs now reads `oober`.
- `scan --format` now validates its value at parse time: an unknown format (e.g. `-f jsonn`) is a hard CLI error listing the accepted values (`text`, `json`, `csv`, `sarif`, `html`). Previously any unrecognized value silently fell back to `text` output. Values keep matching case-insensitively (`-f JSON` still selects JSON output, as before the validation).
- `scan --summary` combined with a non-text `--format` is now an error (`--summary is only supported with --format text`). Previously the flag was silently ignored for `json`, `csv`, `sarif`, and `html` output.
- `replace -d/--dir` is now a legacy alias for a positional input: it is no longer required, and when given it is appended to the positional `<INPUTS>` (so `ob replace src/ -d lib/ ...` processes both). Existing `-d` invocations keep working unchanged; the help text marks the flag as a legacy alias. A replace run with no input at all (and no `--list-presets`) still errors, and the error now names the positional grammar.
- **Breaking:** config files are parsed strictly. An unknown key in a scan patterns file (top level or inside a `patterns` entry) or in a replace config (top level or inside a `blocks` entry) is now an error that names the key, for example ``unknown field `exclusion`, expected `patterns` or `exclusions` ``. Such keys used to be ignored, so a typo such as `replacement:` for `replacements:` silently did nothing. Remove or correct any extra keys in existing configs. The accepted keys are `patterns` (`name`, `pattern`) and `exclusions` for scan, and `patterns`, `replacements`, `blocks` (`start`, `end`), `extensions` and `exclude` for replace.
- **Breaking:** an empty pattern string in a config file is now an error that names the entry (the pattern's `name` in a scan patterns file, the position in a replace config's `patterns` list). An empty regex matches every line in `scan` and at every position in `replace`, so such an entry reported or rewrote everything. The shipped `config/grammar_patterns.yaml` had one: its `bullet` pattern was empty and is now `"\u2022"`.
- **Breaking:** `replace --preset`, `-c/--config`, and `-p/--pattern` are now mutually exclusive: giving more than one is a usage error. Previously they were silently prioritized (preset over config over pattern), so e.g. `--preset clean-debug -p X -r Y` ran the preset and dropped the pattern without a word.
- **Breaking:** the `remove-todos` preset now removes only the comment and keeps the code in front of it, so it leaves lines it used to rewrite. A trailing `TODO`/`FIXME`/`HACK`/`XXX` comment (`//` or `#` style) is cut along with the whitespace before it and the code in front stays; a line holding only such a comment is removed whole, line break included, instead of being left behind empty. The comment marker must start the line or follow whitespace. Previously every pattern began with `.*`, so `chargeCustomer(order); // TODO: retry` and `timeout = compute_timeout()  # TODO: tune` became empty lines, as did lines containing `"http://XXX.example.com"`, `<a href="#TODO">` or `## TODO`; on CRLF files the `\r` was deleted with the line, leaving a bare `\n`.
- **Breaking:** the `clean-debug` preset now only rewrites a debug call that is the whole statement on its own line, so it leaves lines it used to rewrite. `console.log(...)`, `console.debug(...)` and `console.trace(...)` qualify only at the start of a line (after the indent), with arguments that stay on the line and contain no `;`, and with nothing but an optional `;` and whitespace after them; `debugger` only as a whole-line statement; `print(...)  # DEBUG` and `System.out.println(...); // DEBUG` only from the start of a line. The comment stub is unchanged and keeps the line's indent. The `logger.debug(...)` and `Debug.Print(...)` patterns are removed: their `//` stub is not a comment in Python or VB. `DEBUG START`/`DEBUG END` block removal is unchanged. Previously the patterns matched anywhere in a line and up to its last `)`: `items.forEach(x => console.log(x));` became `items.forEach(x => // console.log();`, `console.log(a); return compute(b);` became `// console.log();`, and `if (opts.debuggerEnabled) { start(); }` became `if (opts.// debugger;Enabled) { start(); }`.
- Corrected `scan` help text to state it uses `./patterns.yaml` instead of the misleading "default patterns" wording, and added `-e` usage examples.
- Docs truth pass over README.md and CLAUDE.md: `replace` is no longer described as line-by-line stream processing (it reads each file into memory and applies patterns to whole-file content; `scan` is the streaming path), the scanner's doc comment no longer claims matches are re-confirmed with individual `Regex` objects (the `RegexSet` indices are the result), backup docs state that an existing `.bak` is never overwritten, `chrono` is documented as providing scan report timestamps (not backup timestamps), the README documents `--hidden`/`--no-ignore` and scan's default hidden/gitignore exclusions plus the `--preset` option with its kebab-case names, the incremental-cache location note covers the macOS default, and stale file/module listings (nonexistent `patterns/` collection paths, missing `rename` command and source modules) were corrected.
- All docs now agree on `null` replacement semantics: a `null` entry deletes the line *after* each match, and the matching line itself is kept (unchanged behavior). The CLI help previously claimed "delete line", the README "delete the matched line", and the config docs "no replacement" — three contradictory descriptions of one behavior.
- `rename` now executes serially: renames are metadata operations, and parallel execution raced sibling existence checks (see Fixed). `rename --workers` is still accepted for CLI compatibility but no longer affects execution; `--dry-run` reports the plan and plan-detectable collisions without creating temp files.

- Performance: incremental change detection now compares file metadata first and computes the content hash only when sizes match: with `--incremental --content-hash`, a file whose size changed is no longer read and hashed just to be declared changed.
- Performance: incremental scans now carry the fingerprints computed during change detection into state saving instead of re-fingerprinting every file after scanning. A warm `--incremental --content-hash` run previously read and hashed every unchanged file twice; each file is now fingerprinted at most once per run. Cached results and scan output are unchanged.
- Performance: `replace` now counts matches during the replacement pass itself instead of running a separate `find_iter().count()` pass first, halving the regex work per pattern and per block on every file. Reported change counts and replacement output are unchanged.
- Internal: added a tuned `[profile.release]` (`lto = true`, `codegen-units = 1`, `strip = true`) for a faster, smaller release binary, and removed unused dependencies `anyhow`, `async-trait`, `futures`, and `walkdir` (along with the never-constructed `Error::WalkDir` variant), cutting clean-build and link time.
- Internal: `run_scan` and `run_replace` now take a `ScanOptions` / `ReplaceOptions` struct instead of 14 and 11 positional arguments (mostly same-typed, so prone to transposition); the `#[allow(clippy::too_many_arguments)]` escapes are gone, and `ProcessOptions` derives `Clone, Copy` instead of a hand-written `Clone` impl. CLI behavior is unchanged.
- Internal: deleted dead code — the unused `Formatter` trait, `PatternManager`'s never-called `compile` regex cache (its `load_preset` survives as a free function in `patterns`), the never-called `Scanner::scan_with_progress` (dropping the `indicatif` dependency it existed for), the never-constructed `Error::Processing`/`Error::Utf8` variants, and `BlockPattern`'s unread `start`/`end` fields (compiled blocks are now plain `Regex` values).
- Internal: consolidated duplicated helpers into a shared `util` module: `should_process_file` (the replace path now uses the scanner's O(1) `HashSet` lookup and gains its extension normalization — trim, leading-dot strip, lowercase, empty entries dropped; a filter whose entries all normalize away is rejected, see Fixed), `normalize_extensions` (previously duplicated twice within the scanner), and worker-count resolution (previously copy-pasted across scan, replace, and rename).
- Internal: repository hygiene — `Cargo.lock` is now committed and `Cargo.toml` carries `description` and `rust-version`; a GitHub Actions workflow runs `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test` (the crate is fmt- and clippy-clean); an end-to-end CLI integration suite (`tests/cli.rs`, via `assert_cmd`/`predicates`) exercises the binary; and the flaky wall-clock fingerprint test was replaced with behavioral assertions.
- Internal: removed the unused `num_cpus` dependency (nothing in the crate referenced it; worker counts come from `std::thread::available_parallelism`).
- Internal: deleted `Scanner::scan_directory` and `Scanner::scan_directory_parallel` (and their private `_with_set` helpers). Only the unit tests called them; the CLI collects files with `collect_files` and scans them with `scan_files_parallel`, and the tests now go through that path too. Both were public methods of the library's `Scanner`, so library callers lose them; CLI behavior is unchanged.
- Internal: deleted `Fingerprinter::has_file_changed`, a test-only wrapper around `check_file` (a public library method; callers use `check_file(..).0`), and the `quick_mode` field, which was always the negation of `use_content_hash`.
- Internal: the test suite no longer reads or writes the real user cache or config dir. The `state_manager` unit tests build their manager on a temp dir instead of the resolved cache dir (each run used to leave two JSON files in the user's cache), and the integration suite's `ob()` helper defaults `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` to a per-process temp dir under the cargo target dir; tests that set their own values keep them.

### Fixed

- `replace` now gives explicitly-passed `-x`/`--ext` and `-e`/`--exclude` CLI flags precedence over the config file's `extensions`/`exclude` lists. Previously the config values silently overrode the CLI flags — inverted relative to the usual CLI > config convention — so e.g. `-x py` with a config declaring `extensions: [js]` still processed only `.js` files. Config values now apply only when the corresponding flag is not given.
- `scan` now names the missing patterns file in its error (with a hint to use `-e` or `-p`) instead of emitting a bare `Io(NotFound)`.
- `scan` and `replace` now reject an extension filter whose entries all normalize away (e.g. `-x .`) with a config error (`no valid extensions in -x/--ext`) instead of treating it as no filter. Normalization drops empty entries, and an empty extension set means "process every file" — so an explicit filter that selected nothing silently flipped into processing (and, for `replace`, rewriting) every file in the tree.
- `undo` and `clean-backups` now find `.bak` files that are gitignored (e.g. `*.bak` in the target repo's `.gitignore`); backup discovery previously honored ignore files and reported "Backups found: 0" while backups existed. Discovery walks with gitignore/ignore-file processing disabled but hidden-path filtering still on: `replace` only processes files visible under the standard filters, so a backup it creates can never live behind a hidden path — a `.bak` inside a hidden directory (e.g. a user's own `.config/settings.bak`) is user-owned and is never restored over live files or deleted, and `.git` is never descended into.
- `replace` no longer overwrites an existing `<file>.bak` on repeated runs; the oldest backup is preserved because it holds the pre-oober original, so `undo` restores the true original instead of an intermediate state. (Backups never had timestamps; the docs claiming so are corrected under Changed.)
- `replace` and `rename` now skip `.bak` files entirely. Previously a second `replace` run treated the previous run's backups as ordinary input — rewriting the backup's content in place and stacking a `.bak.bak` on top — so `undo` "restored" content the original file never held; `rename` could similarly rename a backup away from the original it belongs to, breaking `undo`'s name-based pairing.
- `replace` now rejects a config whose `replacements` list is a different length than `patterns`. Previously, missing entries were silently padded with `null` — which means "delete the line after each match" — so an innocent config omission destructively deleted unrelated lines. The error names both lengths; to delete lines intentionally, write an explicit `null` entry.
- `replace` now loads a config that has only `blocks`: `patterns` and `replacements` default to empty lists when the keys are left out. The README's block-only "Remove copyright headers" example used to fail with ``missing field `patterns` ``. A config that gives `patterns` without `replacements` (or the reverse) is still rejected by the length check.
- `replace -p <PATTERN>` without `-r <TEXT>` is now a usage error, and so is `-r` without `-p`. Previously a lone `-p` became a `null` replacement, which means "delete the line after each match", so forgetting `-r` destructively deleted unrelated lines. Library callers of `run_replace` get the same guard as a config error. Deleting the line after a match stays available through a YAML config with an explicit `null` entry.
- `replace` no longer rewrites line endings. The `null`-replacement line-deletion path and the empty-line cleanup after block removal rebuilt files with `\n` regardless of the original line endings, rewriting every line of Windows-encoded files; an interim fix detected a single per-file ending, which converted every LF line to CRLF in mixed-ending files as soon as one CRLF line appeared. Both paths now rebuild from terminator-preserving line segments, so each untouched line keeps its own ending byte-for-byte (trailing newline included).
- `rename` no longer overwrites an existing file when two names map to the same target: all targets are planned and exact duplicates rejected before any rename runs — the colliding rename is skipped with an error naming the target and both files are kept. Previously one file's content was silently destroyed (nondeterministically, under parallel execution) while the summary reported success; an earlier per-file existence check closed only the serial (`-w 1`) case and still raced across parallel workers.
- `rename` is now collision-safe on case-insensitive filesystems (macOS/Windows) and for interdependent renames, via serial two-phase execution for every rename whose target name is occupied: each such source is first moved to a temporary name in its own directory, then each temporary file is moved to its final target, and a target that still exists at that point is refused with the file restored to its original name. Previously: case-variant duplicate targets (`final.txt` vs `Final.txt`) passed the byte-wise plan dedup and the second rename silently destroyed the first file's content while reporting success; case-only renames (`File_1.txt` -> `file_1.txt`) were refused as a collision with the file's own inode; and chained renames (one rename's target equal to another's source, e.g. `a.txt -> ab.txt` while `ab.txt -> abb.txt`) raced the sibling worker and failed half-applied. Chains and swaps (`a <-> b`) now succeed deterministically, case-only renames succeed, and case-variant duplicates fail safely with both contents intact and a non-zero exit.
- `rename` now renames a file directly when its target name is free, and passes only the renames whose target is occupied (a chain, a swap, a case-only rename, or a file outside the plan) through a temporary name. The two-phase execution first moved every planned file to a hidden `.oober-rename-tmp-N` name before the first final rename, so an interrupted run left every file under a temp name with its original name lost. The direct renames run first, and each target is checked again immediately before its rename, so nothing is overwritten.
- `rename` skips files with non-UTF-8 names with a warning instead of panicking (a panic in one worker aborted the entire run mid-rename).
- `rename` rejects a computed target that would leave the file's directory (a replacement containing `/` or `..`) instead of relocating the file outside the tree.
- `rename` now exits non-zero when any rename failed or was skipped due to a collision or an escaping target, and the summary includes an error count.
- `replace` now exits non-zero when any file fails to process (`replace finished with N file(s) failed`), and the summary includes an error count. Previously per-file errors were printed but swallowed, so the process exited 0 even if every file failed.
- `scan` no longer aborts on the first unreadable path: per-entry walk errors (e.g. a permission-denied subdirectory) and per-file read errors (e.g. a permission-denied file) now print a warning to stderr and the scan continues with the remaining files. Previously one unreadable directory or file killed the entire scan (and the parallel walk dropped walk errors silently); scan exits non-zero only on fatal errors such as bad patterns or an unwritable output file.
- `replace`, `rename`, `undo`, and `clean-backups` now warn and continue on per-entry walk errors too, matching `scan`. Previously their walks aborted on the first unreadable path, so a single permission-denied subdirectory meant zero files were processed while `scan` on the same tree warned and continued.
- `replace` now skips binary files, using the same heuristic as `scan` (a null byte in the first 1KB). Previously it tried to read every file as UTF-8 text, so a directory containing images or other binaries produced a per-file error spew — and, combined with the non-zero-exit fix, a spurious failure exit. A skipped binary is not counted as an error.
- All documented preset names now match what the CLI accepts: help text and the no-arg banners showed PascalCase names (`--preset CleanDebug`) that clap rejects; every example now uses the kebab-case form (`--preset clean-debug`), and the replace help lists all seven presets.
- The `replace` confirmation line now echoes the kebab-case preset name the CLI accepts (`Using preset: remove-todos`); it previously printed the Debug form (`Using preset: RemoveTodos`), which clap rejects if copied back into `--preset`.
- The `trim-whitespace` and `remove-empty-comments` presets now work, on CRLF files too: their `^`/`$`-anchored patterns were compiled without `(?m)`, and since `replace` applies patterns to the whole file content, the anchors only matched at file boundaries — `trim-whitespace` was a no-op. Plain `(?m)` anchors still left the presets no-ops on CRLF files, because `$` only matches before `\n` and the trailing `\r` blocked every match. The presets now use `(?mR)` anchors, which treat `\r\n` as a line boundary (`$` sits before the `\r`, so trimming never swallows it); `remove-empty-comments` replaces a knowingly-broken block entry with a whole-content `/\*\s*\*/` pattern, so empty block comments spanning lines (`/*` on one line, `*/` on the next) are still removed. The `replace` help now documents that patterns match whole-file content and that per-line `^`/`$` anchors need `(?m)`.
- `replace` and `rename` now reject a replacement that references a capture group the pattern does not define, before any file is touched. Such a reference used to expand to nothing and silently drop text: `ob replace . -p PRICE -r '$5'` erased every match (group 5 does not exist), and `-r '$2_$1'` lost the second group because `$2_` is a reference to a group named `2_`. The check follows the regex crate's own expansion rule and applies to `-r` and to config-file `replacements` (`null` entries are unaffected); the error names the reference and shows the `${1}` form and `$$` for a literal dollar sign.
- The `rename` help and usage banner no longer ship a reorder example that destroys names. `-p '(\d+)_(.*)' -r '$2_$1'` renamed `01_intro.md` to `01`: `$2_` is read as a reference to a group named `2_`, which does not exist and expands to nothing. The example is now `-p '^(\d+)_(.+?)(\.[^.]+)?$' -r '${2}_${1}${3}'` (`12_intro.md` -> `intro_12.md`), and the `replace` and `rename` help and the README document the `${N}` form and `$$` for a literal dollar sign.
- Fatal errors are now printed in their human-readable `Display` form (`Error: rename finished with 1 error(s)`) with exit code 1; `main` returning `Result` printed the Rust `Debug` form (`Error: RenameFailed(1)`).
- `replace` never processes a symbolic link. A link to a file used to be followed and then replaced: the atomic write renamed a new regular file over the link, so for `docs/README.md -> ../README.md` the link became a plain file, the real `README.md` was left unchanged when the link was reached first, and `undo` did not bring the link back. Symlinks found in a directory walk and symlinks named as inputs are now skipped with one stderr line each (`Skipping symlink: <path>`); the target is edited only under its own path. A directory given as input through a symlink is still walked.
- `replace` no longer rewrites its own config file. With the config inside the processed tree and no extension filter (`ob replace . -c cfg.yaml`), the config was treated as ordinary input: a rule replacing `TODO` with `[TODO]` rewrote the config's own pattern to `[TODO]`, a character class, so the next run replaced every `T`, `O` and `D` in the tree. The resolved config path is now left out of the file list (compared in canonical form, so any spelling of it is caught, including naming it as an input).
- `replace --exclude` (and the config's `exclude` list) now matches names only below each input directory. The check used to compare every component of the full path, so an input that sat under a directory with an excluded name (`ob replace /x/build/app -e build`) processed 0 files and exited 0. Excluded directories are also pruned from the walk now instead of being walked and filtered afterwards. Files named as inputs stay exempt from `--exclude`, as before.
- `scan --incremental` no longer caches a file it could not read. A file that failed to scan (for example mode `000`) was saved in the cache as scanned with no matches; making it readable changes neither its size nor its modification time, so every later run skipped it and its matches were never reported: a false all-clear. Files that fail to scan are now left out of the saved cache and are scanned again on the next run. Saving the cache also no longer fails the run on a file it cannot fingerprint: with `--content-hash`, one unreadable file ended the scan with `Error: IO error: Permission denied` after the results were printed and no cache was saved; such a file is now left out with a warning naming it.
- `scan --incremental` no longer aborts when a cached file cannot be checked for changes. With `--content-hash`, a file that had become unreadable since the last run ended the whole scan with `Error: IO error: Permission denied` before any file was scanned. The scan now warns with the path, treats the file as changed and continues; a file that still cannot be read is skipped with the usual warning and stays out of the cache.
- `scan` now scans a file once when the inputs reach it more than once. A file named explicitly and found again in an input directory, or reached through overlapping directories, was listed once per route: `ob scan . src` printed every match under `src` twice, and `ob scan -i src src/main.rs` read that file's cached matches twice and saved the doubled list, so its match count doubled on every run. Inputs are now deduplicated by canonical path and the first spelling of a path is the one reported. A symlink to a file and its target in the same tree are one file too, so their matches are reported once instead of once per name.
- Incremental caches written before these fixes are dropped once. Such a cache can already hold the bad entries described above (unreadable files recorded as scanned, doubled matches), and it was only invalidated by a tool version or pattern change. Cache files now carry a format number; a cache without the current number is ignored, so the first `scan --incremental` of each project after upgrading scans every file and writes a fresh cache.
- `scan -o FILE` no longer scans its own output file, and no longer truncates it before the inputs are known. The output file was created before the inputs were collected, so with the file inside a scanned directory (`ob scan -e TODO -o results.txt .`) the scan read its own results while writing them and reported them as matches of `results.txt`, and an input path that did not exist emptied an existing results file before the `Input path not found` error. The inputs are now collected first, and the output file is left out of the files to scan (compared by canonical path, so any spelling of it and a symlink to it are caught).
- Scan severities no longer depend on the case of the pattern name. The keyword checks behind the `severity` field (`secret`/`key` for High, `todo`/`fixme` for Low) were case-sensitive, so a pattern named `AWS_KEY` was reported as Medium (SARIF `warning`) instead of High (`error`), and `TODO` as Medium instead of Low (`note`). The name is now lowercased before the checks, in JSON, CSV, SARIF and HTML output alike.

### Security

- SARIF output now emits `artifactLocation.uri` as a working-directory-relative URI with forward slashes (e.g. `src/main.rs`) instead of a raw OS path, which some SARIF consumers reject. A path outside the working directory keeps its absolute form, slash-normalized.
- CSV output now guards against spreadsheet formula injection: any string field starting with `=`, `+`, `-`, or `@` — the (trimmed) matched content, and equally the `Pattern`, `File`, and `Severity` columns, since a scanned file named `=HYPERLINK(...).txt` injects through the `File` column just as well — gets a single-quote prefix, so opening the CSV in Excel, Google Sheets, or LibreOffice renders it as text instead of executing it as a formula. Other output formats are unchanged.
- Config file resolution no longer searches the executable's directory, its parent and grandparent, or `~/.uber_scanner` — a config planted next to the binary (or left over in `target/`) can no longer be picked up silently when the given path has a typo. The `replace` config search is now: the path as given, then the working directory, then `$XDG_CONFIG_HOME/oober` (default `~/.config/oober`); an absolute path is only tried as given, and the not-found error lists exactly the searched locations. `scan -p` deliberately keeps resolving the patterns file only as given (absolute, or relative to the current directory): a typo'd path is an error naming the file (with the `-e`/`-p` hint), never a silent fallback to a same-named stale file in the user config directory — which for a security scan would be a false all-clear. `scan` now reports the patterns file in use on stderr, matching `replace`, which already printed its resolved config.
- The incremental-scan cache (`$XDG_CACHE_HOME/oober/`, default `~/.cache/oober/`) is now owner-only on Unix: the cache directory is created (and, if pre-existing, tightened) to `0700`, and cache files are written with `0600` permissions. The cache stores the matched line contents of previous scans in plaintext — scanning for secrets with `--incremental` copies those matches into it — and was previously world-readable by default. A set-but-empty `XDG_CACHE_HOME` is now ignored like an unset one; it previously resolved the cache dir to the relative `./oober`, dropping the plaintext cache inside the scanned project, where it can get committed. The README now documents the cache location and its contents.
